## 一、虚拟内存与地址转换

### 1. 虚拟内存有什么作用？

**答案：**

虚拟内存为每个进程提供独立、连续的地址空间，由操作系统和 MMU 把虚拟页映射到物理页框。核心作用：

1. 隔离与保护：进程地址空间相互隔离，页表项带读／写／执行权限，越界访问触发异常。
2. 按需分配：物理内存只在首次访问（缺页中断）时才真正分配，进程可以拥有比物理内存更大的地址空间。
3. 共享与映射：共享库、共享内存、内存映射文件让多进程复用同一物理页，节省内存。
4. 简化管理：程序使用连续虚拟地址，不受物理内存碎片影响；配合 swap 可在物理内存不足时把冷页换出。

缺页处理：访问未映射或已换出的页触发缺页异常，操作系统分配物理页、必要时从磁盘调入并更新页表。内存压力大时频繁换页造成抖动（thrashing），性能急剧下降。

### 2. 虚拟地址如何通过页表转换成物理地址？

**答案：**

转换流程：虚拟地址划分为虚拟页号（VPN）和页内偏移；MMU 以 VPN 索引页表，页表项（PTE）给出物理页框号（PFN）和权限位，PFN 拼接页内偏移得到物理地址。整个过程由硬件完成，只有缺页和权限违规才陷入内核。

- 多级页表：x86-64 常用 4～5 级页表，只为实际使用的地址区域分配下级表，解决单级页表在稀疏大地址空间下内存浪费的问题。
- 大页（2MB／1GB）：减少页表项数量和 TLB miss，代价是内部碎片变粗。
- PTE 携带存在位、脏位、访问位和权限位，支撑换页与内存回收决策。

### 3. TLB 是什么？为什么查询很快？满了怎么办？

**答案：**

TLB（Translation Lookaside Buffer）是 MMU 内部的地址翻译缓存，保存最近使用的"虚拟页号 → 物理页框"映射。

快的原因：全硬件实现，采用组相联结构并行比较标签，命中时零额外内存访问，延迟与 L1 缓存同量级；未命中走内存查多级页表则需要 4～5 次内存访问。

- 未命中：由硬件页表遍历器（x86）自动遍历页表并回填。
- 满了：按硬件替换策略（近似 LRU）淘汰旧表项。
- 进程切换：切换页表基址会使旧映射失效，现代 CPU 用 ASID／PCID 给表项标记地址空间编号，避免全量冲刷。

### 4. 32 位和 64 位系统／程序有什么区别？

**答案：**

- 指针宽度：32 位程序指针 4 字节，64 位 8 字节。
- 寻址范围：32 位约 4 GB；x86-64 实际使用 48 位虚拟地址（256 TB）。
- 寄存器：x86-64 通用寄存器数量翻倍（16 个）且为 64 位，函数传参更多走寄存器。
- ABI 类型：`size_t`、`long` 等类型宽度随平台变化。

64 位的代价是指针膨胀带来的内存与缓存压力；收益是更大地址空间、更多寄存器和更好的性能。工程准则：网络协议与文件格式使用固定宽度整数类型，不把指针、`size_t` 直接写入持久化数据。

## 二、CPU 缓存与并发

### 5. CPU 多级缓存如何提高代码和数据访问速度？

**答案：**

存储层级：寄存器 → L1（约 32 KB，4 周期，指令／数据缓存分开）→ L2（几百 KB，十几周期）→ L3（数 MB～几十 MB，几十周期，多核共享）→ 内存（百周期以上）。

工作原理：按缓存行（通常 64 字节）加载内存块，利用时间局部性（刚访问的数据很快再被访问）与空间局部性（相邻地址很快被访问）；硬件预取器识别顺序和固定步长的访问模式提前取数；乱序执行在等待内存时执行其他无依赖指令，隐藏延迟。

对程序的启示：顺序访问数组远快于指针链跳转；数据结构按访问模式排布；热数据集中存放，避免跨缓存行的随机访问。

### 6. 多线程数据竞争的本质是什么？

**答案：**

定义：两个线程访问同一内存位置，至少一方是写，且没有同步（不存在 happens-before 关系）——在 C++／C# 内存模型中属于未定义行为。

关键区分：缓存一致性协议（MESI）保证各核心的缓存行内容一致，但一致性与原子性是两回事——一致性不保证"读—改—写"序列整体原子，也不保证多核看到的操作顺序一致，这些必须靠原子操作和内存序保证。

解决手段：互斥锁、原子操作、线程本地数据、不可变快照、消息传递。另注意逻辑竞态：即使每次访问都是原子的，"先检查再操作"（check-then-act）的组合仍可能违反业务不变量。

### 7. 原子变量在硬件和语言层面如何保证原子性？

**答案：**

语言层面：`std::atomic`／`Interlocked` 定义不可分割的读写及读改写操作，并规定内存序约束，禁止编译器和 CPU 的破坏性重排。

硬件层面：x86 通过 LOCK 前缀指令（`lock xadd`、`lock cmpxchg`）让缓存行在读改写期间独占——现代 CPU 在 L1 内锁定缓存行完成，不再锁总线——配合缓存一致性协议保证所有核心看到同一结果。

边界：对齐且不超过机器字长的类型原生原子；更大或未对齐的类型可能退化为库内加锁（`is_lock_free()` 可查询）。原子性只覆盖单次操作，多个字段的一致更新仍需锁，或把状态打包进单个原子值。

### 8. 锁和原子变量如何选择？lock_guard 为什么能自动解锁？

**答案：**

选择依据：

- 原子变量：单变量计数器、标志位、简单状态机；无阻塞、开销小。
- 锁：多个字段构成不变量、临界区有多步操作、需要配合条件变量等待。
- 高竞争下锁会阻塞／唤醒线程，原子自旋则争用缓存行空转，以实际测量为准。

lock_guard 原理：构造函数调用 `mutex.lock()`，析构函数调用 `unlock()`——RAII 的直接应用。无论正常返回、提前 return 还是异常栈展开，析构都保证执行，锁必然释放。同一模式可封装文件、句柄等任何资源。

### 9. 什么是伪共享？如何处理？

**答案：**

定义：两个线程修改各自独立的不同变量，但变量落在同一缓存行，写操作使其他核心的该缓存行副本反复失效（MESI 乒乓），性能大幅下降。本质是"逻辑不共享、物理共享"。

处理方案：

1. 缓存行对齐／填充：让高频写的变量独占一个缓存行（`alignas(64)`）。
2. 减少共享写：数据按线程分片，本地累积后再合并。
3. 检测：perf／VTune 观察缓存失效与一致性流量异常。

缓存行大小依平台而定，C++17 可用 `std::hardware_destructive_interference_size` 查询；布局调整后以实测收益为准。
